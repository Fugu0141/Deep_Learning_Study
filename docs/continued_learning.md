# 日本語の継続学習実験

このアプリは**事前学習済みの日本語モデルを使いません**。自分で用意したコーパスで小型GPTをゼロから訓練し、その後も重みを引き継いで追加学習できます。

## 手順

1. 「データと設定」で最初の日本語コーパスを入力し、BPEを構築して初回学習します。
2. それとは別に、**学習へ混ぜない固定の日本語文章**を「日本語の習得度テスト」に入力します。最初の1,024文字が測定対象です。
3. 学習中は日本語テストのPerplexity（PPL）と経過秒数を観察します。低いPPLほど、そのテキストの次トークン予測は良好です。
4. 「ファイル → チェックポイントを保存」で重みを保存します。
5. 次回、チェックポイントを読み込み、新しい日本語コーパスに置き換えて「現在のモデルに追加学習」を選びます。
6. 「ファイル → 学習履歴をCSVに保存」でStep・経過秒数・日本語PPL・Validation Lossを記録できます。

「学習Step」は**今回追加する**更新回数です。追加学習で以前のモデルの重みを再初期化しませんが、Optimizerはリセットします。チェックポイント読込直後にも追加学習できます。

## 継続学習の仕組み

- 以前のBPEトークンIDとmergeルールを固定します。
- 新しく登場したUnicode文字がある場合、語彙末尾へ追加します。
- GPTの入力Embeddingと出力Headを拡張し、以前のトークンの埋め込み重みをそのままコピーします。
- 新しい文字に対応する行だけをランダム初期化し、すべてのモデルパラメーターを追加データで更新します。
- 学習済みの重みが新しい学習で変化するため、過去にできたことができなくなる**破滅的忘却**も起こり得ます。

新しい文字を学習できるようにする処理は、単語や文法を理解したこととは異なります。再訓練するのは**言語モデル**であり、トークナイザーのBPE mergeを再構築するわけではありません。

## 比較実験の例

| 段階 | 学習内容 | 確認したいこと |
|---|---|---|
| 0 | ランダム重みから開始 | PPLと生成文の初期値 |
| 1 | ひらがな主体の文章 | 助詞、句点、文字列パターン |
| 2 | 漢字混じりの短文 | 新規文字追加、未知の組み合わせ |
| 3 | 多様な話題の長文 | 学習していない文章への汎化 |
| 4 | 以前の段階の文章でも再評価 | 忘却の有無 |

各段階で、同じ未学習の評価文と生成プロンプトを使い、モデルサイズ、学習率、データ量、実行時間を記録します。一定のPPL値だけで「日本語を習得」と断定せず、文章生成や簡単な質問応答も人間が確認します。

### 測定上の注意

- **学習データと評価テキストを重複させない**でください。同じ文章を暗記しただけでもPPLは低下します。
- 学習時に一度も現れていない文字が評価文にある場合は、UNKとしての予測をPPLに混ぜず**文字網羅率**を表示します。網羅率が100%になってから比較してください。
- PPLは「一つ先のTokenの予測」の指標です。日本語の文法や意味を完全に理解したかどうかの直接的なテストではありません。
- 語彙やBPEルールが異なるモデルのトークン単位PPLをそのまま数値比較するのは避けてください。比較対象のトークナイザーが同じか、評価用のトークン化が変わっていないことを確認してください。
- PPLの算出ではモデルのContext長ごとに評価テキストを区切り、各区間の境界ではそれより前の文脈を使いません。境界や長さを変えないことが再現性の条件です。
- CSVの経過時間は**現在の学習セッション内**で計測します。複数回の追加学習を比較する際は合算してください。
- 初期の学習がかな中心で、評価文に多くの漢字を含む場合、100%の網羅率になるまではスコアがありません。

## 安全性と保管

- チェックポイントはPyTorchファイルです。信頼できない `.pt` ファイルを読み込まないでください。
- 元データ、モデル、ログはユーザーのローカル環境に置かれ、外部のLLM APIは使用しません。
